## Prepared OAuth credential recovery — not executed against deployment

`hollow-lantern/oauth-secret-recovery.mjs` is a prepared recovery tool, not a completed credential repair. Resetting or replacing the live OAuth secret still requires the pending user authorization. The helper does not reset anything in Discord, edit the bot token or base environment, or restart a service.

After that authorization, put the new OAuth client secret alone in an owner-readable local file outside OneDrive. Set `HOLLOW_OAUTH_SECRET_FILE` to that file's absolute path, then run `node hollow-lantern/oauth-secret-recovery.mjs --replace` from the canonical app directory. Do not pass the secret as a command argument or print it. The CLI is pinned to Davy client ID `1540006061099188274` and changes only `DISCORD_CLIENT_SECRET` in `C:/Users/Hermes/Projects/Davy Jones/deployment/.env.native-gateway`.

Before changing the override, it verifies the candidate using Discord's documented Basic-authenticated `client_credentials` grant with `applications.commands.update`. A rejected or interrupted verification leaves the override unchanged. The returned bearer token is discarded. Output contains only a recovery ID and outcome, never response bodies, credentials, or credential hashes. Errors are deliberately generic.

The helper uses a cooperative recovery lock, checks for concurrent target changes, and atomically replaces the override using a staging file in the same directory. It rejects links, hard links, noncanonical/OneDrive paths, duplicate or multiline secret entries, wrong native client IDs, and secret input containing additional configuration. All unrelated configuration bytes remain intact. Backups and the expected replacement are retained in a private recovery folder beneath `C:/Users/Hermes/LocalFiles/hollow-lantern/oauth-recovery/<recovery-id>`. Windows ACLs permit the invoking identity; other explicit and inherited access rules are removed. No hashes are written to the receipt. Backups themselves contain protected environment values and must remain private.

For rollback, set `HOLLOW_OAUTH_RECOVERY_ID` to the successful replacement's recovery ID and run `node hollow-lantern/oauth-secret-recovery.mjs --rollback`. Rollback restores the exact previous file only if the current file still equals the saved replacement. It refuses intervening edits; a repeat rollback reports already restored. Neither operation restarts Davy or the Activity. A leftover lock after a crash is not automatically stolen: inspect the protected before/after files and process state before separately recovering it. A prepared receipt alone does not prove the rename completed.

Validation uses disposable files and fake Discord responses, including rejected credentials, response redaction, concurrent edits, rollback refusal, injection, duplicate entries, wrong client IDs, junctions, and production filesystem-permission handling. No deployment credential replacement has been performed by this task.
